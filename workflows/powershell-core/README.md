# PowerShell 7.4.20 core and real CIM/WMI integration prototype

This builds the original Windows System.Management.Automation, Eventing and
CimCmdlets projects from PowerShell tag v7.4.20, commit
013edf910bbe781f503c27370941ce54d02d3f33. Source archive SHA256:
3dac352752acd64a0502c1f002ecf65eca177d2919bea3bcefbf8856afedd9eb.
The archived tag metadata is retained in the build evidence. No published
PowerShell/SMA implementation or Framework PowerShell runtime is used.

All 697 original Windows SMA C# inputs, nine Eventing inputs, 35 CimCmdlets
inputs, and the original one-file ResGen, TypeCatalogGen and version generator
are checked against the pinned archive. Original project Compile exclusions
are retained. Resources are regenerated by the original ResGen. All original
explicit Documentation/StyleCop/CodeAnalysis analyzers remain enabled, with
source csc49 executing the version and .NET interop generators.

Build adjustments are explicit in source-build-inputs.json:

- Select the installed source SDK8.0.131 instead of the archive's SDK version.
- Use pinned release/commit values in place of git describe in the archive.
- Retarget only the version-generator project to its .NET8 compiler host;
  its C# algorithm remains unchanged.
- Public-sign using the original public key and preserve frozen assembly
  7.4.6.500/file7.4.20.500 identity.
- Build framework-dependent IL without apphost/R2R implementation downloads.
- Preserve generator-output cleanup and exclude persisted generator output
  from Compile so each build regenerates it exactly once.
- Retain upstream EnforceCodeStyleInBuild=true using the installed source
  CodeStyle4.9.2 SDK integration and source csc49. Retain EnableNETAnalyzers=true
  with the exact SDK-selected source .NET analyzers8.0.0-preview.26274.2.
  Explicit source analyzer packages are retained. The original version generator
  has three non-fatal CA1846 suggestions after its.NET8 host retarget.

The type catalog is generated from the complete SMA core reference set, excluding
MMI as upstream does. It is a core bootstrap catalog, not the full PowerShell SDK
catalog; the latter still needs SqlClient/Compatibility and its full project graph.

The embedded source-core check opens a real runspace and executes functions,
loops, built-in pipelines, XML type resolution, PowerShell class compilation,
errors and parser/AST operations. The CIM check imports the original binary
CimCmdlets module and runs local OS/process queries, class metadata, read-only
GetOwner, caught native errors, CIM serialization/deserialization, WMI/CIM inside
one runspace, and GC lifetime checks without Framework implementations.

A native cmdlet error caught by a script can set PowerShell.HadErrors while
leaving no error-stream records. The negative CIM case explicitly requires a
completed invocation, empty unhandled-error stream, and the caught CimException;
unexpected failures remain fatal. Every consumer DLL is matched against the
rebuilt project outputs or the installed source-built NuGet payloads.

In CLANG64, install ${MINGW_PACKAGE_PREFIX}-dotnet-sdk-codestyle and
${MINGW_PACKAGE_PREFIX}-dotnet-sdk-netanalyzers with SDK8.0.131-2 and the source
analyzer/compiler dependencies, extract the pinned archive into a new BUILD_ROOT,
then run:

```bash
python3 prepare.py BUILD_ROOT/PowerShell-7.4.20
bash build.sh BUILD_ROOT
bash check.sh BUILD_ROOT NEW_CORE_CONSUMER
bash check-cim.sh BUILD_ROOT NEW_CIM_CONSUMER
python3 audit-source.py BUILD_ROOT
python3 audit-payload.py BUILD_ROOT NEW_CIM_CONSUMER
```

Consumer restores use a fresh cache and only $MINGW_PREFIX/lib/dotnet/library-packs.
Default SDK file globs are disabled in each consumer so cached source/resource
attachments cannot become test compilation or satellite-resource inputs.
Telemetry is opted out. No persistent WMI/provider or machine configuration
writes are performed.

This is not a complete packaged pwsh application. MMI3 remains an experimental
port with remote/auth/provider-stream/ownership validation open. Full SDK catalog/application/modules, SqlClient/Compatibility,
remaining dependency ports and .NET servicing remain open. The actual runtime
still reports8.0.0; SDK labels and reference aliases are not servicing evidence.
